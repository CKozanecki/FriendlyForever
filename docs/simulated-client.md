# The simulated client

How `spec/support/wow.lua` models the game for the busted specs, and how to extend it. The rules for tests themselves (which kind each criterion needs, chaos-test invariants, mutation checks) are in [CONTRIBUTING.md](../CONTRIBUTING.md#specs-and-traceability) and [AGENTS.md](../AGENTS.md#tests); this file only describes the tool. Where the two differ, CONTRIBUTING.md wins and this file is fixed.

**Source:** everything here describes `spec/support/wow.lua` itself; read it when this file and the code differ, and fix this file. Game facts the model is built on are in [forever-facts.md](forever-facts.md), and the guesses it makes are listed in its ASSUMPTIONS block, checked at the launch test pass (Nov 4, #197) and worked, except the four IDs on #207 and the Salvation, Mass Salvation and Revoke assumptions, which no longer apply: Blizzard removed those spells right before launch (#208). The `[@unit]` cast added since (#198) is unconfirmed: #213.

## What it is

A small simulation of the WoW client API, enough to load the addon as the game does and drive it with events. It is not the game: every behaviour it adds is a claim about WoW Forever, and claims that can't be checked before the game is in hand go in the ASSUMPTIONS block. Those that were in the launch test pass (Nov 4) worked in game, except the four IDs on #207 and the Salvation, Mass Salvation and Revoke ones (removed by Blizzard, #208) (#197).

- **Loading:** `wow.load()` reads `FriendlyForever.toc` and runs each listed file in order with the `(addonName, ns)` varargs, as the game does. `wow.parseToc()` returns the TOC's metadata and file list.
- **Booting:** `wow.boot(opts)` resets the client, loads the addon, fires `ADDON_LOADED` and `PLAYER_ENTERING_WORLD`, and advances past the login grace period. Options:
  - `opts.db`: the saved variables to start with;
  - `opts.before(state)`: change the client's state before the addon loads;
  - `opts.afterLoad(ns)`: change the addon's code once its files are loaded and before its saved settings are, to test a later release (the walkthrough's steps and version, #169);
  - `opts.noGrace`: stop right after login;
  - `opts.buffDefaults`: keep who gets Wisdom, Might and Thorns at their defaults (#219: classes and tanks). Without it, boot sets those three to Everyone unless `opts.db` sets them, so specs aren't surprised by a class left out;
  - `opts.buffSelf`: keep buff mode offering your own copy of your buffs (#198). Without it, boot sets `GroupBuffs.SELF_ORDER` to `"off"`, so specs written before #198 count only the group's casts;
  - `opts.autoBuffMode`: keep buff mode's turn-on triggers at their defaults (on, #72). Without it, boot turns them off unless `opts.db` sets them, so specs that join groups or get buffed don't lend a key by accident;
  - `opts.randomStagger`: keep a guild hello's random extra wait random (#38). Without it, it is always the shortest (`GuildHellos.STAGGER_MIN`), so specs know when a hello goes;
  - `opts.settingsClosed`: keep the settings pages unopened, as in the game until the player opens them (#267). Without it, boot has the Settings window adopt every page (`wow.adoptSettingsPages()`) so specs that read the pages' text see them filled. `Settings.OpenToCategory` adopts, shows and fills one page, running its `OnShow` only if it was hidden; the addon hides its pages when it creates them;
  - `opts.shippedLines`: keep the shipped message lines. Without it, types still on the shipped defaults use the fixed casual lines, since most specs check behaviour rather than wording.
- **State:** `wow.reset()` builds `wow.state` (guild, group, instance, lockdown, combat, units, auras, spells, CVars, clock) and the record tables tests check against:
  - `wow.sent`: chat lines the game accepted; `wow.blocked`: lines it refused;
  - `wow.casts`, `wow.keyActions`, `wow.printed`, `wow.timers`;
  - `wow.landed`: casts the server said landed, `{ spell, id, target, at }`, `at` being when (#37, #36);
  - `wow.flaggedBy` and `wow.flaggedElsewhere`: players whose PvP flag a cast of yours caught (#76);
  - `wow.addonSent`: addon messages the game accepted; `wow.addonRefused`: those it refused, each with its result code; `wow.addonPrefixes`: the prefixes registered (#32).

Chaos tests work out their invariants from these records and from `wow.state`, never by calling the code under test (#73).

## Restrictions it enforces

These mirror real restrictions the addon must live with. Each one makes the client stricter, never looser.

- **Chat** (`SendChatMessage`): text must be a string of at most 255 bytes with no `|`; a whisper needs a target. In chat lockdown (`state.lockdown`) every line is blocked. Outside instances, `/say` and `/yell` need a hardware event (a key press, or a press of a button: `wow.press`, `wow.wheel` through a binding; a click from code is none, #271); text emotes don't (owner, in game, 2026-11-09: #236).
- **Secret values:** `wow.secret(v)` makes a value that raises an error when addon code indexes, compares, measures or does arithmetic on it, and `issecretvalue` recognises it. Lua 5.1 can't make `if secret then` error, intercept `#` on a table, or notice a secret used as a table key (the real client raises an error for that), so specs check that the code never acts on a secret. A check that only keeps a secret out of a table key can't fail a test; #108's `ValidAuraId` is one. Units read as secrets while `state.unitsRestricted` is set, or per field with `unit.secrets = { name = true, ... }`; `wow.lockedAura(id)` is a secret aura whose `auraInstanceID` stays readable. `unit.secrets.auraTimes` makes only a group member's buff times secret (#42). Reading auras raises an error while `state.aurasRestricted` is set.
- **Secure buttons and combat:** protected frame changes and override bindings are refused in combat (`wow.enterCombat()`, `wow.leaveCombat()`), as they are in the game, except in `PLAYER_REGEN_DISABLED`'s handlers. Casts happen only through a key press or click on a secure button (`wow.pressKey`, `wow.press`), and a macro's conditions such as `[help,nodead]` are checked against your target before anything is cast, or against the unit a `[@unit]` names (`[@player,nodead]`, #198), which the cast then goes to without changing your target; an unknown unit casts nothing (unconfirmed in game: #213). When `state.castLandsOn` sends the cast elsewhere, they're checked on the unit it lands on too, and nothing is cast unless both hold (#84).
- **Addon messages** (#32): `C_ChatInfo.RegisterAddonMessagePrefix` and `SendAddonMessage` answer with the 10.2.7+ result codes (`Enum.SendAddonMessageResult`, `Enum.RegisterAddonMessagePrefixResult`). The client refuses:
  - a prefix over 16 characters;
  - a message over 255 bytes;
  - a route you aren't in;
  - a whisper with no target;
  - anything during lockdown or while `state.addonBlocked` is set (an instance under Midnight's rules).

  The game's throttle applies per prefix: 10 at once, then one a second (`wow.ADDON_BURST`, `wow.ADDON_REFILL`). A chaos test can therefore check that the addon never reaches it. `state.noAddonMessages` makes a client without the API.
- **Maps:** `C_Map.GetBestMapForUnit("player")` answers `state.mapId` (1429, Elwynn Forest, by default), and `nil` for any other unit. `wow.setMap(id)` moves you and fires `ZONE_CHANGED_NEW_AREA`; `wow.setMap(id, { silent = true })` moves you with no event, since the addon mustn't rely on one. `wow.CAPITAL` names the six capitals' Classic Era IDs and `wow.ELWYNN` a map that isn't one. `nil` is a map that can't be read, as on a loading screen (#34).
- **Water** (#136): `IsSwimming()`, `IsSubmerged()` and the breath bar (`GetMirrorTimerInfo`, in timer slot 2 rather than the first, with `MIRROR_TIMER_START` and `MIRROR_TIMER_STOP`) follow `wow.swim()`, `wow.dive()`, `wow.surface()` and `wow.leaveWater()`. The bar refills for `wow.BREATH_REFILL_SECONDS` after you surface, then goes (`state.breathStoppedAt`). No event fires for swimming on the surface or climbing out. `wow.inWater()` tells a spec's invariants whether the client's state says you're in the water. `state.waterSecret` makes all three readings secret; specs remove the functions for a client without them. `GetInstanceInfo()` gives the continent and `"none"` in the world, and `state.instanceName` and `state.instanceId` (8th) in a dungeon (`wow.enterDungeon(id, name)`, `wow.leaveDungeon()`); `state.instanceSecret` makes it all secret.
- **Dungeons, raids and members elsewhere** (#256): `wow.enterDungeon(id, name, kind)` takes `IsInInstance()`'s second answer (`"party"` by default), and `wow.enterRaid(id, name)` is the raid form. `wow.zoneOut(token)` puts a group member outside your instance or zone: `UnitIsVisible` says false and `UnitInRange` answers `false, false`. `wow.zoneIn(token)` brings them back. Zoning fires no event, so buff mode's own recheck (`BuffButton.RECHECK_SECONDS`) is what sees them come in. `unit.secrets.hidden` and `unit.secrets.offline` make `UnitIsVisible` and `UnitIsConnected` secret, `unit.secrets.range` does the same for `UnitInRange`, and `state.inInstanceSecret` for `IsInInstance()`. Whether Forever reads a member outside the instance this way is #257.
- **Who cast a group member's buff** (#256): `unit.auraSources[i]` is the caster's unit token. When it isn't set, `wow.boot` reads it as `"player"` (yours), since the game names a group member's caster and most specs mean "they have yours". `false` means the game names no caster, which the addon treats as someone outside the group, so buff mode recasts over it. `opts.unnamedCasters` makes every unset caster read that way. `wow.wearBuff(token, id, { source = false })` puts on a buff with no named caster. A text line's font can be changed with `SetFontObject(<font object name>)`, and its width follows `M.CHAR_WIDTH` for that font. Each line of text is `M.LINE_HEIGHT` tall for its font (#270), and a protected frame's size (`SetSize`, `SetWidth`, `SetHeight`) is locked in combat like its other changes; `GetHeight` reads a frame's height.
- **Group members' buff times** (#42): `unit.auraDurations[i]` and `unit.auraExpires[i]` give aura i's `duration` and `expirationTime` (on `wow.now`'s clock; 0 never runs out). Unset, they're `nil`. A buff whose time has come is gone from `GetAuraDataByIndex`, with no event (`wow.auraExpired(unit, i)` tells a spec's invariants). `wow.wearBuff(token, spellId, { duration, source })` puts one on, an hour by default, replacing one of the same spell as a recast refreshes it.
- **A different buff table:** `wow.boot({ buffTable = t })` loads the addon with `t` in place of the generated `BuffTable.lua`, for specs that need IDs unlike the committed ones (#209).
- **Group versions** (#41): `state.items[itemId]` is how many of a reagent you carry (`GetItemCount` and `C_Item.GetItemCount`; `state.itemsSecret` makes it a secret, and a spec removes the functions for a client without them; `wow.ITEM` names the reagents). `GetRaidRosterInfo(i)` answers for raid slot `i` with the subgroup in its third value (`unit.subgroup`, 1 unless set; `unit.secrets.subgroup` and `state.rosterSecret` make it a secret). Casting a spell in `wow.GROUP_CASTS` fails with no reagent (checked again when the server answers), uses one when it lands, and covers the target's party (in a raid, their subgroup), less anyone offline, dead, out of range or sight. Each covered player then wears the buff from you, flags you if they're flagged and you aren't (`wow.flaggedBy`), and the cast's record in `wow.casts` has `covered`, `before` and `beforeSources` (what each wore, from whom), so a chaos test can check its invariants from the client's own state. In a party you are covered too (you are one of its members); in a raid, when your own raid slot (`setGroup` gives you one, #255) is in the target's subgroup (its record then reads, and the buff is written to, your own buffs, `state.playerAuras`). `wow.tokenFor(unit)` finds a party or raid unit's token. `state.groupBuffSeconds` sets how long the buff lasts (an hour by default), `state.auraDelay` how long it takes to show, and `state.itemNames[itemId]` is the client's name for a reagent (`C_Item.GetItemNameByID`).
- **Greater Blessings** (#41): the group casts in `wow.CLASS_CASTS` (Greater Blessing of Kings, Wisdom and Might) cover every unit of the target's class in the group (`unit.class`; yours is `state.class`) instead of their subgroup, less anyone offline, dead, out of range or sight, and use a Symbol of Kings (`wow.ITEM.symbolOfKings`). Otherwise they behave as the party-wide casts above.
- **Your own raid slot** (#255): `wow.setGroup("raid", names)` (and an instance group in raid slots) also makes you `raidN+1`, N being the others: the same unit table as `player`, so `UnitIsUnit("raidN+1", "player")` is true, `GetRaidRosterInfo` gives your subgroup (`wow.state.units.player.subgroup`, 1 unless set) and `UnitClass` your class. `wow.setGroup("raid", names, false, { noPlayer = true })` leaves it out. Party groups never include you. Chaos specs that pick "someone in the raid" from the `raidN` units must skip the unit that is `state.units.player`.
- **Casts and range** (#260): a cast on a `hidden` unit (including `wow.zoneOut`) fails with `wow.LINE_OF_SIGHT_ERROR`, and one on an `outOfRange` unit with `wow.OUT_OF_RANGE_ERROR`; a cast on yourself never does, and a `castFailures` entry for the target wins. `C_Spell.IsSpellInRange` answers `nil` for a hidden unit and `false` for an `outOfRange` (or `outOfSpellRange`) one.
- **Fonts** (#265): `SetFontObject` takes a font's name or a Font object (a table with `GetName()`; `wow.font(name)`), and an unknown name is an error (`wow.FONTS` lists the known ones, add a name there and to `M.CHAR_WIDTH`/`M.LINE_HEIGHT` for a new font). `GetFontObject` returns the Font object, never the name.
- **Reloads** (#296): `wow.reloadInPlace()` drops every timer the addon scheduled with `C_Timer.After`, as a real `/reload` does, and keeps the game's own (`wow.gameAfter` schedules one: server replies, rosters arriving, the breath bar, addon message echoes). It does not reset the addon's Lua state, so an addon flag like `watching = true` outlives its dropped timer; a spec that must prove a restart at login or reload uses a fresh copy (`wow.newClient`, or `wow.boot` with the roster arriving at `PLAYER_ENTERING_WORLD`).
- **Spells by name:** `C_Spell.GetSpellInfo(name)` and `GetSpellTexture(name)` answer only for spells you know, since the game's name lookup goes through your spellbook; by ID they answer for any spell.

## The ASSUMPTIONS block

The block headed `ASSUMPTIONS ABOUT WOW FOREVER` near the top of `wow.lua` lists every behaviour that is a guess rather than a known fact. Each is a `state` setting where possible, so specs can try the alternatives. Examples: how `/targetexact` spells a two-part name (`state.targetNameForm`), what `UNIT_SPELLCAST_SENT` gives as the target, key-down versus key-up casting, a shown frame's OnHide when it is hidden (#274), the order of a refused cast's error and its `UNIT_SPELLCAST_FAILED`, `state.castLandsOn`, which role APIs exist, how battlegrounds signal their preparation phase (#71), and a group member whose name is still loading (`unit.nameLoading`: `UnitName` gives `UNKNOWNOBJECT`, the surname still comes, and no event fires when it loads; #99).

## Extending it

The rules are in AGENTS.md's [Tests](../AGENTS.md#tests) section; in short:

1. **Realistic.** New behaviour must be something the game does. A test hook that the game can't do (such as `state.castLandsOn`) must still keep the game's rules: #84 found that a cast `state.castLandsOn` redirected skipped the macro's conditions on the unit it landed on, so the client could land a buff on a dead or hostile unit, and 18 of the buff back storm's seeds 1–500 failed for it. Now the conditions are checked there too.
2. **Pessimistic when unsure.** Choose the behaviour that is harder on the addon, and say so in the comment. Examples already in the client: `/targetexact` can't find a player known only as your target; a resurrection in a battleground gives a Preparation aura again; text widths are a little wider than the game's.
3. **Documented.** Add the behaviour to the ASSUMPTIONS block, and, if it is a game fact nobody has confirmed, open a new issue labelled `quality` with the source and how to check it in game.
4. **Test-wide defaults** go in `wow.boot` with an opt-out, like `opts.autoBuffMode`. Read the given saved settings (`opts.db`) before loading fills in defaults, or the opt-out can't tell what the spec asked for.
5. **Tested.** A change to the simulated client is reviewed like addon code, and its own behaviour has tests in `spec/wow_spec.lua`. A change to a test helper after a review approved goes back to that review (#72).
6. **Unknown widget methods** (capitalised names such as `SetJustifyH`) are accepted as no-ops; unset data fields stay `nil`, so a test can't be fooled by a value the client never set. When a test needs a no-op method to do something, give it real behaviour and a test of its own.

## Several clients

For behaviour between two copies of the addon (#32), `wow.newClient({ name, surname, before })` boots a whole client, with its own globals, state and records, and leaves it live. Only one client is live at a time:
- `wow.use(client)` saves the live one and puts another's globals and simulator state in place.
- `wow.network({ a, b })` and `wow.deliver(net)` carry each client's addon messages to the others as `CHAT_MSG_ADDON`, answers included, until none are left:
  - a whisper goes only to the player it names;
  - a group or guild message goes to clients in that group (with the sender in it) or a guild;
  - a group or guild message also comes back to its sender, as in the game. A client in no network hears its own after `wow.ADDON_ECHO_DELAY` (0.2 s), as a timer marked `echo` (#38);
  - a client gets only the prefixes it registered.
- `net.lose = function(msg, sender, receiver)` drops each copy of a message it returns true for, so a chaos test can lose messages at random, as the game may (#36). To lose a message for everyone, sender included (the server dropped it), answer once per `msg` (#38).
- `wow.advanceAll(net, seconds, step)` moves every client's clock on together, delivering after each step.
- `wow.deliverBuffs(net)` carries each buff that landed (`wow.landed`) on another client in the network to that client as a new aura, named by the first unit token (sorted) that shows the caster there, or by none (#37). Pessimistically, a buff that only refreshes one arrives as new (`addedAuras`), so it looks like a new favour; that's in the ASSUMPTIONS block, and was confirmed in game at launch (#37).
- `state.addonSenderForm` (`"hyphen"` or `"space"`) sets how a receiving client spells the sender: confirmed in game at launch (#32).

The network's own behaviour is tested in `spec/wow_comm_spec.lua`.

## Time and randomness

- **Time:** `wow.now` is the game clock (`GetTime()`), starting at 1000; `state.clock` is the wall clock (`time()`). `wow.advance(seconds)` runs due timers in order and moves the clock. Nothing waits in real time.
- **Randomness:** chaos (red) specs use `spec/support/random.lua`, a seeded MINSTD generator, so a seed runs the same storm on every computer. Lua 5.1's `math.random` uses the platform's C `rand()`, so a seed ran one storm on Linux and another on macOS (#76, #87). A failing seed found by hand is added to the spec's committed seed list.
