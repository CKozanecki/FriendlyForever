# The simulated client

How `spec/support/wow.lua` models the game for the busted specs, and how to extend it. The rules for tests themselves (which kind each criterion needs, chaos-test invariants, mutation checks) are in [CONTRIBUTING.md](../CONTRIBUTING.md#specs-and-traceability) and [AGENTS.md](../AGENTS.md#tests); this file only describes the tool. Where the two differ, CONTRIBUTING.md wins and this file is fixed.

**Source:** everything here describes `spec/support/wow.lua` itself; read it when this file and the code differ, and fix this file. Game facts the model is built on are in [forever-facts.md](forever-facts.md), and the guesses it makes are listed in its ASSUMPTIONS block, checked at the launch test pass (Nov 4, #197) and worked, except the four IDs on #207 and the Salvation, Mass Salvation and Revoke assumptions, which no longer apply: Blizzard removed those spells right before launch (#208). The `[@unit]` cast added since (#198) is unconfirmed: #213.

## What it is

A small simulation of the WoW client API, enough to load the addon as the game does and drive it with events. It is not the game: every behaviour it adds is a claim about WoW Forever, and claims that can't be checked before the game is in hand go in the ASSUMPTIONS block. Those that were in the launch test pass (Nov 4) worked in game, except the four IDs on #207 and the Salvation, Mass Salvation and Revoke ones (removed by Blizzard, #208) (#197).

- **Loading:** `wow.load()` reads `FriendlyForever.toc` and runs each listed file in order with the `(addonName, ns)` varargs, as the game does. `wow.parseToc()` returns the TOC's metadata and file list.
- **Booting:** `wow.boot(opts)` resets the client, loads the addon, fires `ADDON_LOADED` and `PLAYER_ENTERING_WORLD`, and advances past the login grace period. Options:
  - `opts.db`: the saved variables to start with;
  - `opts.before(state)`: change the client's state before the addon loads;
  - `opts.afterLoad(ns)`: change the addon's code once its files are loaded and before its saved settings are, to test a later release (the walkthrough's steps and version, #169);
  - `opts.noGrace`: stop right after login;
  - `opts.buffDefaults`: keep who gets Wisdom, Might and Thorns at their defaults (#219: classes and tanks). Without it, boot sets those three to Everyone unless `opts.db` sets them, so specs aren't surprised by a class left out;
  - `opts.buffSelf`: keep buff mode offering your own copy of your buffs (#198). Without it, boot sets `GroupBuffs.SELF_ORDER` to `"off"`, so specs written before #198 count only the group's casts;
  - `opts.autoBuffMode`: keep buff mode's turn-on triggers at their defaults (on, #72). Without it, boot turns them off unless `opts.db` sets them, so specs that join groups or get buffed don't lend a key by accident;
  - `opts.randomStagger`: keep a guild hello's random extra wait random (#38). Without it, it is always the shortest (`GuildHellos.STAGGER_MIN`), so specs know when a hello goes;
  - `opts.guildSync`: send the guild check-ins and line reports (#496). Without it, boot holds them back (`GuildLead.CheckIn` and `GuildLead.ReportLine` send nothing), so specs that count guild addon messages don't see them, and no leader's copy answers one;
  - `opts.settingsClosed`: keep the settings pages unopened, as in the game until the player opens them (#267). Without it, boot has the Settings window adopt every page (`wow.adoptSettingsPages()`) so specs that read the pages' text see them filled. `Settings.OpenToCategory` adopts, shows and fills one page, running its `OnShow` only if it was hidden; the addon hides its pages when it creates them;
  - `opts.shippedLines`: keep the shipped message lines. Without it, types still on the shipped defaults use the fixed casual lines, since most specs check behaviour rather than wording.
- **State:** `wow.reset()` builds `wow.state` (guild, group, instance, lockdown, combat, units, auras, spells, CVars, clock) and the record tables tests check against:
  - `state.inRaidUnreadable`, `state.inGroupUnreadable`: `IsInRaid()` or `IsInGroup()` answers a secret (#322). In a raid, `party1` to `party4` are the other members of your own subgroup (`wow.state.units.partyN`, found on demand, never keys);
  - `button:Click(mouseButton, down)` runs PreClick, OnClick and PostClick with `down` false unless given, and is no hardware event (#285);
  - `wow.sent`: chat lines the game accepted; `wow.blocked`: lines it refused;
  - `wow.casts`, `wow.keyActions`, `wow.printed`, `wow.timers`;
  - `wow.landed`: casts the server said landed, `{ spell, id, target, at }`, `at` being when (#37, #36);
  - `wow.flaggedBy` and `wow.flaggedElsewhere`: players whose PvP flag a cast of yours caught (#76);
  - `wow.addonSent`: addon messages the game accepted; `wow.addonRefused`: those it refused, each with its result code; `wow.addonPrefixes`: the prefixes registered (#32).

Chaos tests work out their invariants from these records and from `wow.state`, never by calling the code under test (#73).

## Restrictions it enforces

These mirror real restrictions the addon must live with. Each one makes the client stricter, never looser.

- **Chat** (`SendChatMessage`): text must be a string of at most 255 bytes with no `|`; a whisper needs a target. In chat lockdown (`state.lockdown`) every line is blocked. Outside instances, `/say` and `/yell` need a hardware event (a key press, or a press of a button: `wow.press`, `wow.wheel` through a binding; a click from code is none, #271); text emotes don't (owner, in game, 2026-11-09: #236).
- **Secret values:** `wow.secret(v)` makes a value that raises an error when addon code indexes, compares, measures or does arithmetic on it, and `issecretvalue` recognises it. Lua 5.1 can't make `if secret then` error, intercept `#` on a table, or notice a secret used as a table key (the real client raises an error for that), so specs check that the code never acts on a secret. A check that only keeps a secret out of a table key can't fail a test; #108's `ValidAuraId` is one. Units read as secrets while `state.unitsRestricted` is set, or per field with `unit.secrets = { name = true, ... }`; `wow.lockedAura(id)` is a secret aura whose `auraInstanceID` stays readable. `unit.secrets.auraTimes` makes only a group member's buff times secret (#42). Reading auras raises an error while `state.aurasRestricted` is set.
- **Strangers on nameplates** (#39): a unit's `cantAssist` makes `UnitCanAssist("player", unit)` false (the other faction, a duel), as `hostile` does, and fails a macro's `[help]`; `inCombat` makes `UnitAffectingCombat(unit)` true. `unit.secrets.canAssist` and `unit.secrets.combat` make those answers secrets. `opts.autoBuffMode` keeps the campfire trigger (`autoOnCampfire`) on too: it is one of `wow.TURN_ON_TRIGGERS`. Unconfirmed in game: #414.
- **Secure buttons and combat:** protected frame changes and override bindings are refused in combat (`wow.enterCombat()`, `wow.leaveCombat()`), as they are in the game, except in `PLAYER_REGEN_DISABLED`'s handlers. Casts happen only through a key press or click on a secure button (`wow.pressKey`, `wow.press`), and a macro's conditions such as `[help,nodead]` are checked against your target before anything is cast, or against the unit a `[@unit]` names (`[@player,nodead]`, #198), which the cast then goes to without changing your target; an unknown unit casts nothing (unconfirmed in game: #213). When `state.castLandsOn` sends the cast elsewhere, they're checked on the unit it lands on too, and nothing is cast unless both hold (#84).
- **Addon messages** (#32): `C_ChatInfo.RegisterAddonMessagePrefix` and `SendAddonMessage` answer with the 10.2.7+ result codes (`Enum.SendAddonMessageResult`, `Enum.RegisterAddonMessagePrefixResult`). The client refuses:
  - a prefix over 16 characters;
  - a message over 255 bytes;
  - a route you aren't in;
  - a whisper with no target;
  - anything during lockdown or while `state.addonBlocked` is set (an instance under Midnight's rules).

  The game's throttle applies per prefix: 10 at once, then one a second (`wow.ADDON_BURST`, `wow.ADDON_REFILL`). A chaos test can therefore check that the addon never reaches it. `state.noAddonMessages` makes a client without the API.
- **Maps:** `C_Map.GetBestMapForUnit("player")` answers `state.mapId` (1429, Elwynn Forest, by default), and `nil` for any other unit. `wow.setMap(id)` moves you and fires `ZONE_CHANGED_NEW_AREA`; `wow.setMap(id, { silent = true })` moves you with no event, since the addon mustn't rely on one. `wow.CAPITAL` names the six capitals' Classic Era IDs and `wow.ELWYNN` a map that isn't one. `nil` is a map that can't be read, as on a loading screen (#34).
- **Water** (#136): `IsSwimming()`, `IsSubmerged()` and the breath bar (`GetMirrorTimerInfo`, in timer slot 2 rather than the first, with `MIRROR_TIMER_START` and `MIRROR_TIMER_STOP`) follow `wow.swim()`, `wow.dive()`, `wow.surface()` and `wow.leaveWater()`. The bar refills for `wow.BREATH_REFILL_SECONDS` after you surface, then goes (`state.breathStoppedAt`). No event fires for swimming on the surface or climbing out. `wow.inWater()` tells a spec's invariants whether the client's state says you're in the water. `state.waterSecret` makes all three readings secret; specs remove the functions for a client without them. `GetInstanceInfo()` gives the continent and `"none"` in the world, and `state.instanceName` and `state.instanceId` (8th) in a dungeon (`wow.enterDungeon(id, name)`, `wow.leaveDungeon()`); `state.instanceSecret` makes it all secret.
- **Dungeons, raids and members elsewhere** (#256): `wow.enterDungeon(id, name, kind)` takes `IsInInstance()`'s second answer (`"party"` by default), and `wow.enterRaid(id, name)` is the raid form. `wow.zoneOut(token)` puts a group member outside your instance or zone: `UnitIsVisible` says false and `UnitInRange` answers `false, false`. `wow.zoneIn(token)` brings them back. Zoning fires no event, so buff mode's own recheck (`BuffButton.RECHECK_SECONDS`) is what sees them come in. `unit.secrets.hidden` and `unit.secrets.offline` make `UnitIsVisible` and `UnitIsConnected` secret, `unit.secrets.range` does the same for `UnitInRange`, and `state.inInstanceSecret` for `IsInInstance()`. Forever reads a member outside the instance as not visible: confirmed in game (owner, 2026-11-14, #257). How it reads a member inside but far away is still unconfirmed (#257).
- **Who cast a group member's buff** (#256): `unit.auraSources[i]` is the caster's unit token. When it isn't set, `wow.boot` reads it as `"player"` (yours), since the game names a group member's caster and most specs mean "they have yours". `false` means the game names no caster, which the addon treats as someone outside the group, so buff mode recasts over it. `opts.unnamedCasters` makes every unset caster read that way. `wow.wearBuff(token, id, { source = false })` puts on a buff with no named caster. A text line's font can be changed with `SetFontObject(<font object name>)`, and its width follows `M.CHAR_WIDTH` for that font. Each line of text is `M.LINE_HEIGHT` tall for its font (#270), and a protected frame's size (`SetSize`, `SetWidth`, `SetHeight`) is locked in combat like its other changes; `GetHeight` reads a frame's height.
- **Group members' buff times** (#42): `unit.auraDurations[i]` and `unit.auraExpires[i]` give aura i's `duration` and `expirationTime` (on `wow.now`'s clock; 0 never runs out). Unset, they're `nil`. A buff whose time has come is gone from `GetAuraDataByIndex`, with no event (`wow.auraExpired(unit, i)` tells a spec's invariants). `wow.wearBuff(token, spellId, { duration, source })` puts one on, an hour by default, replacing one of the same spell as a recast refreshes it.
- **A different buff table:** `wow.boot({ buffTable = t })` loads the addon with `t` in place of the generated `BuffTable.lua`, for specs that need IDs unlike the committed ones (#209).
- **Group versions** (#41): `state.items[itemId]` is how many of a reagent you carry (`GetItemCount` and `C_Item.GetItemCount`; `state.itemsSecret` makes it a secret, and a spec removes the functions for a client without them; `wow.ITEM` names the reagents). `GetRaidRosterInfo(i)` answers for raid slot `i` with the subgroup in its third value (`unit.subgroup`, 1 unless set; `unit.secrets.subgroup` and `state.rosterSecret` make it a secret). Its second value is the rank (#497): 2 for the raid's leader (you with `state.isLeader`, another named by `state.leader`, as `UnitIsGroupLeader` answers), 1 for an assistant (`unit.assistant`), 0 otherwise; `unit.raidRank` sets it outright, and `unit.secrets.rank` makes it a secret, as do `state.isLeaderUnreadable` (your own slot) and `state.leaderUnreadable` (the others'), since a game that hides who leads would hide the rank too (unconfirmed on Forever: #528). Casting a spell in `wow.GROUP_CASTS` fails with no reagent (checked again when the server answers), uses one when it lands, and covers the target's party (in a raid, their subgroup), less anyone offline, dead, out of range or sight. Each covered player then wears the buff from you, flags you if they're flagged and you aren't (`wow.flaggedBy`), and the cast's record in `wow.casts` has `covered`, `before` and `beforeSources` (what each wore, from whom), so a chaos test can check its invariants from the client's own state. In a party you are covered too (you are one of its members); in a raid, when your own raid slot (`setGroup` gives you one, #255) is in the target's subgroup (its record then reads, and the buff is written to, your own buffs, `state.playerAuras`). `wow.tokenFor(unit)` finds a party or raid unit's token. `state.groupBuffSeconds` sets how long the buff lasts (an hour by default), `state.auraDelay` how long it takes to show, and `state.itemNames[itemId]` is the client's name for a reagent (`C_Item.GetItemNameByID`).
- **Greater Blessings** (#41): the group casts in `wow.CLASS_CASTS` (Greater Blessing of Kings, Wisdom and Might) cover every unit of the target's class in the group (`unit.class`; yours is `state.class`) instead of their subgroup, less anyone offline, dead, out of range or sight, and use a Symbol of Kings (`wow.ITEM.symbolOfKings`). Otherwise they behave as the party-wide casts above.
- **Your own raid slot** (#255): `wow.setGroup("raid", names)` (and an instance group in raid slots) also makes you `raidN+1` (not in a full raid of 40), N being the others: the same unit table as `player`, so `UnitIsUnit("raidN+1", "player")` is true, `GetRaidRosterInfo` gives your subgroup (`wow.state.units.player.subgroup`, 1 unless set) and `UnitClass` your class. `wow.setGroup("raid", names, false, { noPlayer = true })` leaves it out. Party groups never include you. Chaos specs that pick "someone in the raid" from the `raidN` units must skip the unit that is `state.units.player`. In the game a raid also gives your own subgroup's other members as `party1..4`; the simulated client doesn't, so a spec that needs them adds them by hand (#335's `moltenCore` in `spec/pvp_dungeon_spec.lua`, and `spec/group_unreadable_spec.lua` for #322) until #322's harness change models them. A raid of 40 others, with no slot for you, is one more than the game allows: "everyone is inside" reads it as nobody inside, since no raid slot is you (#335).
- **Casts and range** (#260): a cast on a `hidden` unit (including `wow.zoneOut`) fails with `wow.LINE_OF_SIGHT_ERROR`, and one on an `outOfRange` or `outOfSpellRange` unit with `wow.OUT_OF_RANGE_ERROR`; a cast on yourself never does, and a `castFailures` entry for the target wins. `C_Spell.IsSpellInRange` answers `nil` for a hidden unit and `false` for an `outOfRange` (or `outOfSpellRange`) one.
- **Fonts** (#265): `SetFontObject` takes a font's name or a Font object (a table with `GetName()`; `wow.font(name)`), and an unknown name is an error (`wow.FONTS` lists the known ones, add a name there and to `M.CHAR_WIDTH`/`M.LINE_HEIGHT` for a new font). `GetFontObject` returns the Font object, never the name.
- **Reloads** (#296): `wow.reloadInPlace()` drops every timer the addon scheduled with `C_Timer.After`, as a real `/reload` does, and keeps the game's own (`wow.gameAfter` schedules one: server replies, rosters arriving, the breath bar, addon message echoes). It does not reset the addon's Lua state, so an addon flag like `watching = true` outlives its dropped timer; `wow.reloadInPlace(login, { keepTimers = true })` keeps the timers too, for a chaos storm that reloads repeatedly (dropping them would wedge flags like `watching` for the rest of the run). A spec that must prove a restart at login or reload uses a fresh copy (`wow.newClient`, or `wow.boot` with the roster arriving at `PLAYER_ENTERING_WORLD`).
- **Group roles** (#408): `UnitGroupRolesAssigned` answers a group unit's `unit.role` (`"TANK"`, `"HEALER"`, `"DAMAGER"`, or `"NONE"` when unset: no role chosen), and `GetPartyAssignment("MAINTANK", unit)` its `unit.mainTank` in a raid only. `unit.secrets.role` and `unit.secrets.mainTank` make either answer a secret. That Forever gives HEALER and DAMAGER once roles are chosen is the owner's fact ([forever-facts.md](forever-facts.md)).
- **Chat from players** (#40): `wow.whisper(text, sender)`, `wow.say(text, sender)` and `wow.party(text, sender, leader)` fire `CHAT_MSG_WHISPER`, `CHAT_MSG_SAY` and `CHAT_MSG_PARTY` (`CHAT_MSG_PARTY_LEADER` with `leader`) with the game's 17 arguments, text first and the sender second (and again fifth). The sender is passed as the spec gives it; `"First-Surname"` is the game's form as far as anyone knows (unconfirmed for these events: #352). Either may be a `wow.secret`, as chat inside an instance can be (#32).
- **Ranks** (#434): `/cast <name>` casts the highest rank of that name you know, by rank, never by spell ID (some ranks' IDs aren't in rank order: Forever's Trueshot Aura ranks 1 and 2, 1299346 and 1299348, are above rank 5's 20906). Each `nameSpell` list is highest rank first, and `wow.SPELL_RANK[id]` holds `{ name, rank }` (1 the lowest); `spec/wow_spec.lua` checks the order against `BuffTable.lua`'s ranks, from Forever's data. A spell a spec names by hand (`wow.SPELL_NAMES[id] = name`) has no rank: when no known ID of the name has one, the highest ID is cast. Classic Era behaves this way; Forever is unconfirmed (#437).
- **Rank levels and ranked casts** (#459): `wow.SPELL_LEVEL[id]` is each rank's level, read with `dofile` from the committed `scripts/data/forever-spell-levels.lua` (Forever's `SpellLevels` data), never from `BuffTable.lua`, so specs work out the expected rank on their own. A cast on another player fails with `wow.LOW_LEVEL_ERROR` ("Target is too low level") when their level plus `wow.LEVEL_MARGIN` (10) is below the rank's level: the server rule as Classic's emulators have it, unconfirmed on Forever (#463); never for a group version (unknown, #463) or a cast on you. A player with no `unit.level` is `state.defaultLevel`, which `wow.boot` sets to 60 (`opts.defaultLevel`: another level, or `false` for none, so `UnitLevel` answers nil and the server takes level 1). `/cast Name(Rank 3)` casts exactly the known spell of that name with that rank text; `GetSpellSubtext` and `C_Spell.GetSpellSubtext` give `wow.spellSubtext(id)`: "Rank N" for a name of several ranks (a spec's renamed spell keeps its rank), "" for one of one, `state.spellSubtexts[id]` overriding it; `state.noSpellSubtext` takes both away and `state.secretSubtext` makes them secrets. `wow.lastResult(ns)` reads the button's last result from `/friendly buffback`, since a press's line under the button goes once it offers another player (#461).
- **The realm and several characters** (#508): `GetRealmName()` answers `state.realm`, "Forever Realm" by default; `state.secretRealm` makes it a secret. `spec/percharacter_spec.lua` logs in as several characters by booting again with the saved settings (`wow.boot({ db = _G.FriendlyForeverDB, before = ... })`) after `PLAYER_LOGOUT`, as the game does. Settings given to `wow.boot` without a `schemaVersion` are a spec's current settings: their weapon fields are put back after migration 9's one-time reset, and they (with `wow.boot`'s other defaults) become the seed each new character copies; a spec that gives a `schemaVersion` gets the real migration and seed. Each new character sees the walkthrough's step about its own settings once; `wow.boot` counts it as seen unless `opts.welcome`.
- **Self-buffs** (#44): `wow.SELF_SPELLS` names each self-buff spell by its IDs, which Forever's spell data gives at Classic Era's (highest rank first in `wow.SELF_RANKS`; `spec/bufftable_spec.lua` checks the generated table against it), with its duration (Classic Era's, except Trueshot Aura's 30 minutes, from Forever's data), whether it's a toggle and its family. Omen of Clarity is named but isn't a self-spell: it's a passive on Forever. Cast on you, its aura goes on from you after the server's answer (later with `state.auraDelay`), replacing your others of its family; a toggle never runs out. `/cast !Spell` casts nothing while that toggle of yours is on, and `/cast Spell` without `!` switches it off (`cast.toggledOff`). `C_Spell.IsSpellUsable` and `IsUsableSpell` answer from `state.unusable[name]` (`"power"` or `"other"`), and an unusable spell's cast fails; `IsMounted`, `UnitOnTaxi`, `GetShapeshiftForm` and `UnitPowerType` follow `state.mounted`, `state.onTaxi`, `state.form` and `state.powerType`, and `state.selfSecrets` makes them secrets. Your own buffs drop out past their time only with `state.expirePlayerAuras`. The committed buff table holds the self-buffs since #44's second part, so specs use it as it is. All of it is in the ASSUMPTIONS block; durations and the rest are unconfirmed in game: #326.
- **Weapon buffs** (#45): `state.equipped[slot]` is the item worn in slot 16 or 17 (a sword in the main hand by default), described in `wow.GEAR_INFO` (class 2 a weapon, 4 armour; `use`, a weapon's own Use). `state.weaponEnchants[slot]` is the temporary enchant on it (`wow.enchant(slot, id, seconds)`; `wow.enchantOn(slot)` reads it, and it's gone past its time), which `GetWeaponEnchantInfo` gives as four values per slot, as Forever does. `wow.WEAPON_ITEMS` holds some of the stones, oils and poisons with the spell each casts and its enchant, and `wow.IMBUES` some shaman imbue ranks, all from Forever's data (`spec/weaponbuffs_data_spec.lua` checks them). `/use item:<id>` takes an item you carry up to be put on a weapon, and `/use 16` or `/use 17` puts it on that slot's weapon (a cast, sent naming the weapon as its target, never a player, and answered like any other, `state.weaponRefusal` making the server refuse it; `state.useDoesNothing` makes `/use item:<id>` do nothing at all); with nothing waiting, `/use 16` fires the weapon's own Use, recorded in `wow.weaponUses`, which the addon must never do. An imbue cast puts its enchant on the main hand by itself, or, with `state.imbuePicks`, waits for `/use 16` or `/use 17` to pick the weapon, as an item does. Every one lasts `wow.WEAPON_BUFF_SECONDS`. A druid in a form or a shaman in Ghost Wolf: with `autoUnshift` on (the default), the game cancels the form and carries on, counted in `wow.formsCancelled` (the owner accepts that, as by hand: #45); with it `"0"`, the game refuses. A stone goes only on the weapons it suits (`fits` and `edge`: sharpening on a blade, weights on a blunt one), and on another the game refuses at once with `wow.WRONG_WEAPON_ERROR`. `state.unusableItems[id]` makes an item unusable (`IsUsableItem` answers from that alone, never from how many you carry), and `state.weaponSecrets` (`enchants`, `equipped`, `itemInfo`, `itemSpell`, `usable`, or `error` for an error) makes those answers secret. All of it is in the ASSUMPTIONS block; what is unconfirmed is on #409.
- **Druid forms** (#452): `state.form` is your form (0: none), which `GetShapeshiftForm` gives (`state.selfSecrets.form` makes it secret). `wow.setForm(n)` changes it and fires `UPDATE_SHAPESHIFT_FORM`, as the game does. Every buff spell is "not while shapeshifted", as in Forever's data: cast in a druid's form or Ghost Wolf, the game cancels the form and carries on (`autoUnshift` on, the default, counted in `wow.formsCancelled`), or refuses with `wow.SHAPESHIFT_ERROR` (`"0"`). A secure button's action is looked up under the pressed button's suffix as Blizzard's `SecureButton_GetButtonSuffix` gives it (`wow.buttonSuffix`): `"1"` to `"3"` for the mouse's left, right and middle buttons, the number for `Button4` to `Button31`, and `"-" .. name` for any other, such as buff mode's key (`BuffModeKey`). What is unconfirmed is on #454. A shaman's Ghost Wolf (#466): `wow.setGhostWolf(on)` sets `state.ghostWolf`, your form (`state.ghostWolfForm`, 1 unless set) and an aura of `wow.GHOST_WOLF` (2645) on you, unless `state.ghostWolfAura` is false. Then it fires `UNIT_AURA` and `UPDATE_SHAPESHIFT_FORM`. A spec can model either way Forever might report Ghost Wolf (#467): form 0 with the aura, or the form with no aura. The game stops a cast in Ghost Wolf either way, and cancelling it takes both away. Moonkin Form (#485): `wow.setForm(n, spellId)` also names the form's spell (`wow.MOONKIN_FORM` 24858, `wow.CAT_FORM`, `wow.BEAR_FORM`, `wow.TRAVEL_FORM`, `wow.AQUATIC_FORM`, Classic Era's IDs), which `GetShapeshiftFormInfo(n)` gives as its fourth answer for the form you're in, and `GetShapeshiftFormID` gives its number from `wow.FORM_IDS` (Moonkin 31). `state.formId` overrides the number (`false`: none), `state.formInfoError` makes `GetShapeshiftFormInfo` fail, and `state.selfSecrets.formInfo` and `.formId` make them secrets. A druid in Moonkin Form casts every buff without leaving it (the owner), but an item's use (a weapon buff) still stops there. Forever's IDs are unconfirmed: #488.
- **Indoors** (#510): `IsIndoors()` answers `state.indoors` (false by default), a boolean as Forever's API documentation gives it; a function there answers in its place, for a spec that breaks it. No event fires when it changes (whether the game fires one is unconfirmed, #511), so the addon reads it at each arming of the buff button.
- **Guild roster zones** (#486): `GetGuildRosterInfo(i)` answers its sixth value, the zone, from `state.guildZones[name]`, else `""` (not filled in yet, the pessimistic case, quality issue #487); `state.guildZoneSecret` (true, or a set of names) makes it a secret. Its ninth value is whether they're online (`state.guildOffline`).
- **Guild chat** (#496): `wow.guildChat(text, sender)` fires `CHAT_MSG_GUILD` with the game's arguments, text and sender first. In a network, `wow.deliver` carries every line a client said in guild chat to every client in a guild, its own sender included, as the game does. A line from a client in no guild (`state.inGuild ~= true`) reaches no one, its sender included, as the game refuses it ("You are not in a guild."). It's refused when it is sent: `wow.sent` records it with `refused = true`, and joining a guild afterwards doesn't revive it (#531).
- **Guild ranks** (#496): `GetGuildRosterInfo(i)` answers its third value, the rank index, from `state.guildRanks[name]` (`wow.DEFAULT_GUILD_RANK`, 4, when unset; 0 is the guild master), and its second, the rank's name, from `state.guildRankNames`; `state.guildRankSecret` (true, or a set of names) makes the index a secret. `GetGuildInfo("player")` gives `state.guildName` ("Friends Forever"; nil while not loaded, a secret with `state.guildNameSecret`), your rank's name and index, and no realm. `GetServerTime()` is `time()` plus `state.serverSkew`, a secret with `state.serverTimeSecret`. All unconfirmed on Forever: #523.
- **Guild rank names** (#496 part 3): `GuildControlGetNumRanks()` answers `state.guildNumRanks` (5; nil makes it unreadable). `GuildControlGetRankName(i)` answers `state.guildRankNames[i - 1]`, else `"Rank i"`: i = 1 is the guild master's, so roster rank index r is name r + 1. It answers nothing past the count, and `state.guildRankNameSecret` makes the names secrets. Unconfirmed on Forever: #533.
- **Layout edges and scrolling** (#482): nothing is laid out, so `GetTop` and `GetBottom` answer `region.top` and `region.bottom` as a spec sets them, or nil (not laid out). `GetChildren` and `GetRegions` give a frame's own child frames and its text lines and textures, in the order they were made, and a `UIPanelScrollFrameTemplate` frame has its `ScrollBar`. A spec of the options' scroll heights places the rows it needs and leaves the rest unplaced; the UI simulator measures the real layout.
- **Spells by name:** `C_Spell.GetSpellInfo(name)` and `GetSpellTexture(name)` answer only for spells you know, since the game's name lookup goes through your spellbook; by ID they answer for any spell.

## The ASSUMPTIONS block

The block headed `ASSUMPTIONS ABOUT WOW FOREVER` near the top of `wow.lua` lists every behaviour that is a guess rather than a known fact. Each is a `state` setting where possible, so specs can try the alternatives. Examples: how `/targetexact` spells a two-part name (`state.targetNameForm`), what `UNIT_SPELLCAST_SENT` gives as the target, key-down versus key-up casting, a shown frame's OnHide when it is hidden (#274), the order of a refused cast's error and its `UNIT_SPELLCAST_FAILED`, `state.castLandsOn`, which role APIs exist, how battlegrounds signal their preparation phase (#71), and a group member whose name is still loading (`unit.nameLoading`: `UnitName` gives `UNKNOWNOBJECT`, the surname still comes, and no event fires when it loads; #99).

## Extending it

The rules are in AGENTS.md's [Tests](../AGENTS.md#tests) section; in short:

1. **Realistic.** New behaviour must be something the game does. A test hook that the game can't do (such as `state.castLandsOn`) must still keep the game's rules: #84 found that a cast `state.castLandsOn` redirected skipped the macro's conditions on the unit it landed on, so the client could land a buff on a dead or hostile unit, and 18 of the buff back storm's seeds 1–500 failed for it. Now the conditions are checked there too.
2. **Pessimistic when unsure.** Choose the behaviour that is harder on the addon, and say so in the comment. Examples already in the client: `/targetexact` can't find a player known only as your target; a resurrection in a battleground gives a Preparation aura again; text widths are a little wider than the game's.
3. **Documented.** Add the behaviour to the ASSUMPTIONS block, and, if it is a game fact nobody has confirmed, open a new issue labelled `quality` with the source and how to check it in game.
4. **Test-wide defaults** go in `wow.boot` with an opt-out, like `opts.autoBuffMode`. Read the given saved settings (`opts.db`) before loading fills in defaults, or the opt-out can't tell what the spec asked for.
5. **Tested.** A change to the simulated client is reviewed like addon code, and its own behaviour has tests in `spec/wow_spec.lua`. A change to a test helper after a review approved goes back to that review (#72).
6. **Unknown widget methods** (capitalised names such as `SetJustifyH`) are accepted as no-ops; unset data fields stay `nil`, so a test can't be fooled by a value the client never set. When a test needs a no-op method to do something, give it real behaviour and a test of its own.

## Strata, levels and clicks (#427)

Every frame has a strata and a level (`SetFrameStrata`, `SetFrameLevel` and their getters): a new frame takes its parent's strata and the parent's level + 1. `wow.hitTest(frames)` says which of some overlapping frames gets a click: only shown frames that take the mouse count (a Button does unless `EnableMouse(false)`, another frame only after `EnableMouse(true)`), the highest strata wins, then the highest level. Two frames tied on both have no defined winner in the game, so it returns `nil` and the list of tied frames; a spec that expects a winner fails on a tie. `spec/dropdown_levels_spec.lua` uses it for every options dropdown. The facts are in [forever-facts.md](forever-facts.md#frame-levels-and-mouse-clicks-427). It models no screen position: the spec names the frames that overlap.

## Several clients

For behaviour between two copies of the addon (#32), `wow.newClient({ name, surname, before })` boots a whole client, with its own globals, state and records, and leaves it live. Only one client is live at a time:
- `wow.use(client)` saves the live one and puts another's globals and simulator state in place.
- `wow.network({ a, b })` and `wow.deliver(net)` carry each client's addon messages to the others as `CHAT_MSG_ADDON`, answers included, until none are left:
  - a whisper goes only to the player it names;
  - a group or guild message goes to clients in that group (with the sender in it) or a guild;
  - a group or guild message also comes back to its sender, as in the game. A client in no network hears its own after `wow.ADDON_ECHO_DELAY` (0.2 s), as a timer marked `echo` (#38);
  - a client gets only the prefixes it registered.
- `net.lose = function(msg, sender, receiver)` drops each copy of a message it returns true for, so a chaos test can lose messages at random, as the game may (#36). To lose a message for everyone, sender included (the server dropped it), answer once per `msg` (#38).
- `wow.advanceAll(net, seconds, step)` moves every client's clock on together, delivering after each step.
- `wow.deliverBuffs(net)` carries each buff that landed (`wow.landed`) on another client in the network to that client as a new aura, named by the first unit token (sorted) that shows the caster there, or by none (#37). Pessimistically, a buff that only refreshes one arrives as new (`addedAuras`), so it looks like a new favour; that's in the ASSUMPTIONS block, and was confirmed in game at launch (#37).
- `state.addonSenderForm` (`"hyphen"` or `"space"`) sets how a receiving client spells the sender: confirmed in game at launch (#32).

The network's own behaviour is tested in `spec/wow_comm_spec.lua`.

## Time and randomness

- **Time:** `wow.now` is the game clock (`GetTime()`), starting at 1000; `state.clock` is the wall clock (`time()`). `wow.advance(seconds)` runs due timers in order and moves the clock. Nothing waits in real time. A timer the addon schedules with a delay too small to move the clock (about `1e-13` at `now` near 1000) runs at the same time, and one that reschedules itself that way never lets `advance` return: `Comm.Pump`'s send bucket can do it after many sends (#325). Until #325 is fixed, a storm that returns many favours and doesn't test the hidden channel stubs `ns.Comm.Send`, as #316's does.
- **Randomness:** chaos (red) specs use `spec/support/random.lua`, a seeded MINSTD generator, so a seed runs the same storm on every computer. Lua 5.1's `math.random` uses the platform's C `rand()`, so a seed ran one storm on Linux and another on macOS (#76, #87). A failing seed found by hand is added to the spec's committed seed list.
